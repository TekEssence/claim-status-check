# MedRevenue Availity

Select MedRevenue → Eligibility Verification → Availity. Upload the eligibility workbook and the existing Availity login workbook (Project = MedRevenue, Portal = Availity, Link, Username, Password, optional Secret Key). Without Secret Key, the frontend prompts for a verification code when Availity displays the code field. With Secret Key, the existing automatic authenticator flow is used. Credentials from Minimax are never used.

`../config/projects/index.ts` selects the project configuration, following Waystar's default/override pattern. Minimax has no overrides and continues through its existing payer registry. MedRevenue selects the member-search inquiry mode and reuses the existing Availity browser, authentication, and credential reader. Its output uses `buildWaystarOutputWorkbook` with `projectId: "medrevenue"`; the formatter is unchanged.

The confirmed payer mapping is Molina / Molina Healthcare / Molina Healthcare California → MOLINA HEALTHCARE CALIFORNIA. Add further confirmed aliases and exact portal payer names in `../config/projects/medrevenue.ts`. Payer values are resolved from Primary Insurance Name, never from a fixed value in the automation. Unmapped rows are left unprocessed, including rows belonging to other portals. A workbook with no mapped rows fails with an explanatory message.

Required input columns: Primary Insurance Name, Member ID, DOB (or Date of Birth), DOS (or Date of Service). Patient Name or first/last name helps identify returned members. Dedicated workbooks may omit Project; explicitly marked rows from other projects are excluded. Original worksheet row numbers and DOS values are preserved.

Provider Alkhouri, Wadie (NPI 1568556652) and state California are configured only for MedRevenue. Provider selection always clicks the dropdown entry matching both the name and NPI, then checks that the selection survives leaving the field. Typed text alone is insufficient; WADIE ALKHOURI MD INC is not selected. A unique member-ID match, or name plus DOB match, is required before Submit. Ambiguous results fail the row. A failed row closes the session so the next patient starts without stale results. Missing response fields generate a warning and blank output values; coverage retains the common active/inactive/unknown conventions and the displayed text is kept in result metadata.

Tests in `../tests/medrevenue.test.ts` cover routing, credentials, member matching, output columns and a local browser fixture. Set `AVAILITY_BROWSER_TESTS=1` to include the Chrome fixture. These tests do not access a live Availity account.

Result extraction waits for values beneath the supplied labels, including nested wrappers and inline text in the result iframe. Current Plan Effective Date maps the dates before and after the range separator to Eff Date and End Date. Period Start Date maps to Plan Date; Insurance Type maps to Bot Insurance Type; Plan / Product maps to Plan Type. Unavailable or invalid response dates leave only those date fields blank; invalid dates produce a warning and the original fields remain in result metadata. `../tests/result-fields.test.ts` verifies delayed result values through the generated Excel columns.
